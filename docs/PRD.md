## 1. 产品概述

### 1.1 背景

企业招聘初筛环节存在大量重复、耗时的人工面试工作。借助大语言模型（LLM）与语音技术，可以让 AI 扮演面试官，自动提问、追问并产出结构化评估，将 HR 从初筛中解放出来，同时保证筛选标准的一致性和可追溯性。

### 1.2 产品定位（一句话）

一款面向企业招聘的 AI 面试工具：HR 配置一场 AI 面试（选用内置题库模板或粘贴 JD 自动生成题目），候选人通过链接进入、以「实时文字对话 + 语音辅助」完成面试，AI 自动提问、追问、评分，并产出结构化评估报告，作为**初筛第一轮**的依据。

### 1.3 目标用户

- **企业端用户**：HR / 面试官 / 企业管理员 —— 创建面试、管理候选人、查看报告、做筛选决策。
- **候选人**：求职者（注册账户）—— 收到邀请、参加面试、查看结果（可选）。

### 1.4 核心价值

- 对 HR：5 分钟配置一场面试，自动完成初筛，报告可追溯、可复核。
- 对候选人：免于反复填写重复信息，体验接近真实面试的对话，作答自然。
- 对企业：统一筛选标准，减少主观偏差，提高初筛效率与人才漏斗质量。

### 1.5 成功标准（首版）

1. 一场面试可在 HR 侧 5 分钟内配置完成并发出邀请。
2. 候选人完成一场约 20–30 分钟的面试，AI 全程无卡顿、追问自然。
3. 报告产出含分数、维度分、逐题点评与通过建议，HR 可据此快速做出初筛判断。

## 2. 范围界定

### 2.1 首版（V1，本 PRD 范围）

- PC 端 Web。
- 文字实时对话 + 语音辅助（TTS 朗读 + 语音转写）。
- 企业端 + 候选人端双端。
- 内置题库模板 + JD 生成题目。
- 评估报告（总分/维度分/逐题点评/通过建议）。

### 2.2 明确不做（V2 及以后）

- 移动端（App / 移动 Web 优化）。
- 双向全实时语音对话。
- 视频面试、表情/微表情分析。
- 多语言（英文面试等）。
- 候选人端自主练习 / 开放题库（C 端自我练习产品）。
- HR 自定义上传题目（首版仅选模板或 JD 生成）。

## 3. 用户角色与权限

| 角色 | 说明 | 权限 |
|------|------|------|
| 企业管理员 | 企业内部最高权限 | 组织与成员管理、席位/套餐、所有面试与报告、系统配置 |
| HR / 面试官 | 实际使用方 | 创建/编辑面试、邀请候选人、查看报告、复核标注 |
| 候选人 | 求职者 | 注册登录、参加被邀请的面试、查看结果（由企业控制） |

候选人只能访问自己被邀请的面试，无法访问企业端任何数据。

## 4. 功能需求

> 以下功能需求编号 FR-xx，供后续实现计划与验收引用。

### 4.1 企业端

#### 4.1.1 账户与组织

- **FR-01 企业注册/登录**：企业账户注册与登录（邮箱 + 密码，预留 SSO 扩展）。
- **FR-02 成员管理**：管理员可邀请、停用、删除成员，并分配「管理员 / HR/面试官」角色。
- **FR-03 席位与套餐**：首版计费从简，仅保留「席位数 / 面试场次」概念用于用量统计与后续计费。

#### 4.1.2 面试管理

- **FR-04 创建面试**：填写面试名称、岗位信息；可粘贴岗位 JD；选择题目来源（题库模板 或 JD 生成）；设置题量、时长、评分维度权重、通过阈值；保存为草稿或直接发布。
- **FR-05 面试列表**：按状态（草稿 / 进行中 / 已结束）展示，支持搜索、筛选、复制、编辑、删除。
- **FR-06 面试配置字段**：岗位名称、JD、题目集、题量（默认 5–8 题）、单场时长上限（默认 45 分钟）、维度权重、通过阈值（默认 60/75 两档）。

#### 4.1.3 题库模板

- **FR-07 内置题库**：按行业 / 岗位 / 能力维度分类的模板库。
- **FR-08 模板详情**：每个模板含题目列表、考察维度、参考评分要点，HR 可预览。

#### 4.1.4 JD 生成题目

- **FR-09 JD 解析生成**：HR 粘贴 JD 后，AI 生成题目 + 考察维度 + 评分要点。
- **FR-10 生成结果编辑**：HR 可预览、增删、编辑生成的题目后发布。

#### 4.1.5 候选人管理

- **FR-11 邀请候选人**：生成带签名的邀请链接/面试码，分享给候选人（复制链接）。
- **FR-12 候选人名单与状态**：已邀请 / 已参加 / 已完成的状态跟踪与列表。

#### 4.1.6 报告查看与评审

- **FR-13 报告列表**：按候选人/面试维度列出已完成面试的报告。
- **FR-14 报告详情**：总分、维度得分（雷达图）、逐题点评与亮点/不足、通过建议 + 推荐理由。
- **FR-15 人工复核**：HR 标注「通过 / 淘汰 / 待定」并补充备注；支持按分数排序、筛选。
- **FR-16 原始转写查看**：可点开查看完整文字对话转写（含语音转写），用于复核与合规追溯。

### 4.2 候选人端

- **FR-17 注册/登录**：邮箱或手机号注册登录。
- **FR-18 面试大厅**：查看被邀请的面试（待参加 / 已完成）。
- **FR-19 面试前准备**：设备检测（麦克风）、阅读面试须知、隐私与录音授权同意。
- **FR-20 参加面试**：逐题作答（文字或语音转写），AI 追问，实时文字对话流式呈现。
- **FR-21 面试提交**：面试结束后提交，进入评分，可查看「已出报告」状态。
- **FR-22 结果可见性**：是否向候选人展示详细结果由企业端配置，首版默认不开放详细结果。

## 5. 核心用户流程

### 流程 A：企业发布面试

1. HR 登录 → 创建面试 → 填写岗位信息（可粘贴 JD）。
2. 选题：选用题库模板，或 JD 生成 → 预览编辑。
3. 设置维度权重、题量、通过阈值。
4. 保存/发布 → 生成邀请链接。
5. 分享链接给候选人。

### 流程 B：候选人参加面试

1. 点击邀请链接 → 注册/登录 → 进入面试详情。
2. 设备检测 + 阅读须知 + 授权同意。
3. 开始面试 → AI 开场提问 → 逐题作答 → AI 追问 → … → 收尾。
4. 提交，等待评分出报告。

### 流程 C：HR 评审

1. 查看已完成面试的报告列表。
2. 打开报告：分数 + 维度分 + 逐题点评 + 通过建议。
3. 人工复核，标注通过/淘汰/待定，决定是否进入下一轮。

## 6. AI 面试引擎设计

### 6.1 流程控制（状态机）

面试状态：`未开始 → 进行中（开场 → 题1 → [追问] → 题2 → … → 收尾）→ 已完成 → 评分中 → 已出报告`。

- **开场**：AI 自我介绍并说明流程规则。
- **主体**：按预设题目顺序逐题提问。
- **追问**：AI 根据回答判断是否追问（回答过短、不完整、有亮点需深挖），每题追问上限 1–2 次。
- **收尾**：询问是否有补充 → 结束语。

### 6.2 实时文字对话

- AI 每句回复通过 SSE 或 WebSocket 流式输出；候选人文字即时发送。

### 6.3 语音辅助

- **TTS**：AI 的题目/追问可朗读，候选人可开关。
- **ASR**：候选人语音输入 = 前端录音 → 上传后端 → 转写为文字 → 作为候选人消息进入对话。

### 6.4 评分机制

- 面试过程中 AI 后台记录每道题回答要点。
- 面试结束后做一次**结构化评分**（维度打分 + 逐题点评 + 亮点/不足 + 通过建议）。
- 首版「单次生成 + 结构化校验」保证格式可靠；「多次打分取一致」作为后续增强。

## 7. 评分与报告

### 7.1 评分维度（默认可配权重）

| 维度 | 默认权重 | 说明 |
|------|---------|------|
| 专业技能 | 40% | 与岗位匹配的知识/能力 |
| 逻辑思维 | 25% | 分析、结构化、论证 |
| 沟通表达 | 20% | 清晰度、条理、语言组织 |
| 岗位匹配度 | 15% | 经验、动机、价值观匹配 |

- 分数：0–100 分制（维度分 + 总分）。
- 通过建议：结合总分与阈值，AI 给出「建议通过 / 建议待定 / 建议淘汰」+ 推荐理由。

### 7.2 报告内容

- 总分与维度得分（雷达图）。
- 逐题点评与亮点/不足。
- 通过建议 + 推荐理由。
- 后台保留原始文字转写（含语音转写），供复核与合规追溯，非主视图但可查看。

## 8. 非功能需求

### 8.1 性能

- AI 文字流式回复首字延迟 < 2s。
- 普通页面加载 < 2s。
- 首版目标：支持约 100 场面试并发。

### 8.2 安全

- 认证用 JWT；企业端与候选人端账户体系分离。
- 角色授权：管理员 / HR/面试官分级；候选人仅能访问被邀请的面试。
- 传输层 TLS；录音、转写、JD/简历等敏感数据加密存储。
- 邀请链接带签名并支持有效期，防滥用。

### 8.3 隐私合规（中国 PIPL，重点）

- 候选人参加前需明确授权「录音 / 语音转写 / AI 分析」。
- 数据最小化、用途限定；支持数据留存策略、删除权、导出权。

### 8.4 可靠性与可观测

- 面试中断可恢复；服务可用性目标约 99.5%。
- 接入日志、监控、告警。

## 9. 技术架构概览

### 9.1 前端（Vue 3）

- Vue 3 + TypeScript + Vite + Pinia + Vue Router。
- UI 库：Element Plus 或 Naive UI（待定）。
- 通过 SSE/WebSocket 接收 AI 流式回复；`getUserMedia` 采集麦克风（仅录音，非实时通话）。

### 9.2 后端（FastAPI）

- 分层：路由层（薄）→ 服务层（编排 AI 调用）→ 数据访问层（SQLAlchemy ORM）。
- 模块划分：`auth`（认证）、`org`（组织/成员）、`interview`（面试配置与会话）、`question`（题库/JD 生成）、`evaluation`（评分/报告）、`voice`（ASR/TTS 封装）、`candidate`（候选人）。

### 9.3 数据存储

- **PostgreSQL**：用户、组织、面试、题目、会话、消息、评分、报告等结构化数据。
- **Redis**：会话状态、流式对话上下文、限流、任务队列。
- **对象存储**（MinIO / 云 OSS）：录音与转写文件。
- **向量库**：首版可选（JD 出题若用检索增强），非必须。

### 9.4 第三方 AI 服务

- **LLM**：对话、出题、评分（选型需兼顾数据合规与效果，倾向国内合规或可私有化部署的模型）。
- **ASR / TTS**：语音识别与合成（国内云厂商）。

### 9.5 关键数据实体

`User`（企业用户 / 候选人，分类型）、`Organization`、`Membership`、`Interview`（配置）、`InterviewSession`（候选人单场会话）、`Message`（对话消息）、`Question`（题目）、`Evaluation`（评分）、`Report`、`Invitation`。

## 10. MVP 里程碑

- **M1 基础**：企业注册/登录、成员与权限、候选人注册/登录。

## 11. 风险与开放问题

| 风险/问题 | 说明 | 应对 |
|-----------|------|------|
| 评分可靠性与公平性 | AI 打分存在偏差 | 人工复核兜底 + 评测集持续验证 |
| 隐私合规 | 录音/语音数据的授权与留存 | 明确授权流程，最小化留存 |
| LLM 供应商选型 | 效果与数据合规的取舍 | 待定，需对比国内合规/私有化方案 |
| 语音成本 | ASR/TTS 用量与费用 | 用量统计与成本控制策略 |
| 实时性/并发 | 流式对话与并发的稳定性 | SSE/WebSocket 方案 + 压测 |
