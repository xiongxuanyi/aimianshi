## 1. 项目概述

「面试大师」是一款面向企业招聘的 AI 初筛面试工具。本工程实现其**候选人端**：候选人通过企业邀请进入，以「实时文字对话 + 语音辅助」完成面试，AI 面试官自动提问、追问、评分并生成报告。

本阶段（Release 1.0.0）聚焦候选人端 6 大功能点：

| 编号 | 功能 | 对应界面 |
|------|------|---------|
| FR-17 | 注册/登录 | 登录页 `LoginView` |
| FR-18 | 面试大厅 | 大厅 `HallView` |
| FR-19 | 面试前准备（设备检测/须知/隐私授权） | 准备页 `PrepView` |
| FR-20 | 参加面试（实时文字对话 + 语音辅助 + 追问） | 面试页 `InterviewView` |
| FR-21 | 面试提交（评分中状态） | 完成页 `CompleteView` |
| FR-22 | 结果可见性（默认不开放详细结果） | 结果页 `ResultView` |

## 4. 架构设计

采用「视图层 → 状态层 → 数据层」三层结构，前后端分离：

```
┌─────────────────────────────────────────────────────────┐
│  视图层 (views / components / layouts)                    │
│  - 只负责渲染与用户交互，通过 store 读写状态               │
├─────────────────────────────────────────────────────────┤
│  状态层 (Pinia stores)                                    │
│  - auth：登录态 + 持久化                                  │
│  - interview：面试列表                                    │
├─────────────────────────────────────────────────────────┤
│  数据层 (api/mock.ts)                                     │
│  - 模拟接口（带延迟的 Promise）                            │
│  - 后续替换为 axios 即可接入真实后端                        │
└─────────────────────────────────────────────────────────┘
         │（未来）
         ▼
   FastAPI 后端（interview/backend）
```

**关键设计决策：**

1. **Mock 数据层与真实 API 解耦**：`api/mock.ts` 暴露 `fetchInterviews` / `fetchInterview` / `getInterviewScript` 三个带模拟延迟的异步函数，接口签名与真实后端一致，后续只需替换实现、无需改动视图与 Store。
2. **登录守卫**：`router.beforeEach` 统一拦截——未登录访问受保护页跳转登录页；已登录访问登录页跳转大厅。
3. **Element Plus 主题化**：通过 CSS 变量 `--el-color-primary` 等覆写，使组件库与自研设计系统（品牌色 #4F46E5）视觉统一，而非默认蓝。

## 5. 路由设计

| 路径 | 名称 | 组件 | 说明 |
|------|------|------|------|
| `/login` | login | LoginView | 登录/注册（无需登录） |
| `/` | — | AppLayout | 应用外壳（需登录） |
| `/hall` | hall | HallView | 面试大厅（默认首页） |
| `/prep/:id` | prep | PrepView | 面试前准备 |
| `/interview/:id` | interview | InterviewView | 实时面试对话 |
| `/complete` | complete | CompleteView | 提交完成 |
| `/result/:id` | result | ResultView | 结果可见性 |
| `/:pathMatch(.*)*` | — | 重定向 | 兜底跳转 `/hall` |

`/prep/:id`、`/interview/:id`、`/result/:id` 通过路由参数携带面试 ID，页面按 ID 从 Mock 层查询详情，未命中则提示并回退大厅。

## 6. 状态管理（Pinia）

### 6.1 auth.ts（登录态）

- `token` / `userName`：登录令牌与用户名，持久化到 `localStorage`（刷新不掉线）。
- `isLoggedIn`：计算属性，由 token 决定。
- `login(account)`：邮箱取前缀、手机号取原值作为展示名。
- `logout()`：清空状态与本地存储。

### 6.2 interview.ts（面试数据）

- `list`：候选人被邀请的面试列表。
- `loading`：加载状态（驱动大厅 `v-loading`）。
- `loadInterviews()`：调用 Mock 接口拉取列表。

## 7. 数据层与 Mock 设计

### 7.1 领域类型（types/index.ts）

- `InterviewStatus`：`pending`（待参加）/ `evaluating`（评分中）/ `reported`（已出报告）。
- `Interview`：面试实体（岗位、企业、题量、时长、状态、有效期/提交时间等）。
- `ChatTurn`：AI 面试官的一段台词及其对应题号（用于进度）。
- `ChatMessage`：对话消息（`ai` / `user` 角色 + 打字状态）。

### 7.2 Mock 数据

- **4 条面试邀请**：覆盖三种状态（1 待参加、1 评分中、2 已出报告）。
- **1 份 AI 面试剧本**：内置「高级 Java 后端工程师」6 题剧本，含开场白、2 次追问与收尾，共 10 段台词，用于驱动面试对话与进度推进。

> 说明：真实系统中题目由「题库模板 / JD 生成」配置决定；此处为本地可跑通而内置一份剧本，已在代码注释中标注。

## 9. UI/UX 设计规范

**设计原则**：专业、可信、冷静克制——候选人处于紧张状态，界面强调「公正、清晰、可预期」，弱化花哨元素。

| 项 | 值 |
|----|----|
| 主色（品牌） | `#4F46E5`（靛蓝），深色 `#4338CA` / `#3730A3` |
| 辅助色（AI 属性） | `#7C3AED`（紫罗兰） |
| 成功 / 警告 / 危险 | `#059669` / `#D97706` / `#DC2626` |
| 背景 / 表面 | `#F6F7FB` / `#FFFFFF` |
| 文字 | 主 `#0F172A`，次 `#64748B`，弱 `#94A3B8` |
| 圆角 | 大 16px / 中 12px / 小 10px |
| 阴影 | 三级（sm / md / lg），md 级带品牌色偏 |
| 字体 | 系统字体栈（PingFang SC / Microsoft YaHei 优先） |
| 品牌渐变 | `linear-gradient(135deg, #4F46E5, #7C3AED)` |

## 10. 核心交互流程

```
登录 → 大厅 → 进入面试 → 面试前准备 → 开始面试 → 实时对话 → 结束提交 → 返回大厅
```

1. 登录页任意账号密码登录（演示）→ 大厅。
2. 大厅点击「进入面试」→ 准备页。
3. 准备页：检测麦克风（可选）→ 阅读须知 → 勾选 3 项隐私授权 → 开始面试。
4. 面试页：AI 开场白 + 第 1 题流式呈现；逐题作答（文字或按住说话），AI 追问；进度条与计时实时推进。
5. 右上角「结束面试」→ 确认弹窗 → 提交 → 完成页（评分中）。
6. 大厅中「已出报告」的面试可「查看结果」，展示结果可见性说明。

## 13. 已知问题与后续规划

**已知问题 / 可优化项：**

1. Element Plus 全量引入导致首包偏大，建议后续改按需引入或 `manualChunks` 分包。
2. 语音输入为原型模拟（定时器生成示例文本），真实 ASR 需接入后端语音服务。
3. AI 剧本为单份内置数据，真实系统应由面试配置动态下发。

**后续规划：**

1. 企业端（HR）全套界面：登录/工作台/面试管理/创建面试/题库/JD 生成/候选人管理/报告（含雷达图，用 echarts）。
2. 将 Mock 层替换为 axios，对接现有 FastAPI 后端。
3. 接入真实 ASR/TTS 与 SSE 流式对话。
4. 结果页按企业配置开放详细评分报告。
